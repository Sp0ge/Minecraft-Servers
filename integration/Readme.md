# Клиентские проверки

Запускайте только на локальной тестовой сети: `home.js` размещает тестовую кровать и платформу в survival около (100,100,100).

Установите зависимости в этом каталоге через `npm ci` в Node 24. Контейнер клиента должен иметь сеть `mcservers_internal`, этот каталог в `/tests`, том `mcservers_secrets` только для чтения в `/secrets`, рабочий каталог `/tests`.

- `node smoke.js`: AuthMe, запрет неавторизованного перехода, автоматический выбор Pillars, survival другой версии, сброс пустой арены, прямой выбор и lobby.
- `node tpa-peer.js` и `node home.js` запускаются одновременно в двух отдельных контейнерах: кровать, разрушенная кровать, отклонение и принятие TPA.

Аккаунты MCNetTestA/MCNetTestB и их пароли сохраняются между проверками. Пароли, зависимости и файлы синхронизации исключены из Git. После завершения клиенты отключаются. Платформа остаётся в тестовом мире.

## KiwyClub

`kiwy.js` — обычная функциональная проверка двумя клиентами: регистрация с одного IP,
книга, справка, меню/TAB, победа и новый сид parkour, переименование готового резерва
Pillars и удаление пустого мира. Создаёт только свои временные KCTest-аккаунты,
удаляет их после успешного завершения; при прерывании удалите оставшиеся fixtures.
`status-check.js` проверяет публичный MOTD, иконку 64×64 и лимит 64 через status ping.
Эти проверки не запускаются стартовым скриптом и не создают нагрузку из десятков клиентов.
